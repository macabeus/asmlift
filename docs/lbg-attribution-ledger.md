# LoadBGTilemapData attribution — hypothesis ledger and exclusions

This is the round's negative record: what was asked, what was done to answer it, and what the
answer licenses. It is the durable half of a working handoff whose other half — sequencing,
environment notes and verbatim copies of the studies linked from
[the attribution plan](lbg-attribution.md) — is not reproduced here.

"Rejected" rejects the stated inference; it does not mean no effect was measured. An ownership
boundary is not proof that a particular guard fired. Numbers carried from a study are that study's
measurements; where this round re-ran one, the row says so.

## What was excluded, and why

### No new inverse allocator

Observed allocator state is not an algorithm for recovering source declarations from final machine
code. An inverse would need post-optimization RTL references, live lengths, conflicts, register
classes and allocation history. The instrumented compiler observes those for supplied C; it does
not recover them from the target. No transformation considered in this round both reproduced a
target pattern and supplied an independently minimized failing round-trip. The deliverable is a
recorded missing capability with L3 feedback ownership, not an invented algorithm.

### No rows for unminimized full-function perturbations

The split, merge and address experiments have scores, but they are full-function source
interventions rather than isolated gaps. `spillorder`/`spillorder_rev` already cover the verified
spill law, and the out-parameter and address families own the memory semantics the address
experiment adds. A row per curve point would lengthen the dataset without isolating a capability.

### No aggregate explanation for the remaining 182 rows

That residual has several populations. The ownership table points at existing constant-address
shaping, declaration and slot construction, structuring and scoring boundaries — places a future
hypothesis would be investigated, not causes observed to fire here. Assigning every unmatched
region to one broad label justifies no implementation.

### Ideas closed before this round were not reopened

The 383 spelling/ablation, sound-pruning fan reduction, zero-winning-family deletion, live
global-base local, DMA pointer hoist, tree-level reassociation, per-function predicate for
per-site licensing, computed-jump frontend, and shared 28-byte layout ideas were already closed.
This round did not rerun them and claims none of their numbers as new. Nothing measured here
falsifies those closures: in particular this function still gives no basis for a jump-table
frontend, and the tree-associate explanation remains refuted.
